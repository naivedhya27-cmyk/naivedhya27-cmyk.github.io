How to export 30 days with every seat

macOS or Linux, with a team admin API key in CURSOR_ADMIN_KEY:

END=$(($(date +%s) * 1000)); START=$((END - 30 * 86400000))
curl -s -X POST https://api.cursor.com/teams/daily-usage-data \
  -u "$CURSOR_ADMIN_KEY:" -H "Content-Type: application/json" \
  -d "{\"startDate\": $START, \"endDate\": $END, \"page\": 1, \"pageSize\": 1000}" > usage.json

Windows PowerShell:

$end = [DateTimeOffset]::UtcNow.ToUnixTimeMilliseconds(); $start = $end - 30 * 86400000
$auth = [Convert]::ToBase64String([Text.Encoding]::ASCII.GetBytes("$($env:CURSOR_ADMIN_KEY):"))
Invoke-RestMethod -Method Post -Uri https://api.cursor.com/teams/daily-usage-data `
  -Headers @{ Authorization = "Basic $auth" } -ContentType 'application/json' `
  -Body (@{ startDate = $start; endDate = $end; page = 1; pageSize = 1000 } | ConvertTo-Json) |
  ConvertTo-Json -Depth 6 | Set-Content usage.json

Without page and pageSize the API returns active users only, which hides the seats that never started. One request covers at most 30 days; for a longer period, or more than 1,000 seats, put the responses in one array.

How the readout decides

These are my starting thresholds. With a customer they are agreed with the team in the first week, and the readout then runs every week on the same export.

MeasureFlagged belowWhy it matters
Seats that used it at least once60%Activation comes before depth: unused seats are the first conversation.
Active seats using it on most working days40%A habit, not a trial. Most working days means at least 60% of weekdays in the file.
Agent share of requests25%Agent is where one instruction carries the most work; chat alone leaves that on the table.
Tab acceptance25%The first place to look is the repository rules and docs the model works from.
Active seats on the newest client70%Every seat should have the same features and fixes before results are compared.
